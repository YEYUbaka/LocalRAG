## 一、MySQL基础

### Q1: MySQL索引是什么？为什么能加速查询？⭐⭐

**简答：**
> 索引是帮助MySQL高效获取数据的数据结构，类似书的目录。通过B+树实现，将O(n)的全表扫描优化为O(logn)的树查找。

**详细回答：**

**索引的本质：**
索引是存储引擎用于快速找到记录的一种数据结构。InnoDB使用B+树作为索引结构。

**为什么能加速查询：**
- 无索引：全表扫描，逐行比较 → O(n)
- 有索引：B+树查找，每次比较排除一半数据 → O(logn)

**索引类型：**
1. **主键索引**：PRIMARY KEY，唯一且不为空
2. **唯一索引**：UNIQUE，值唯一但可为空
3. **普通索引**：INDEX，无限制
4. **全文索引**：FULLTEXT，用于文本搜索
5. **组合索引**：多个列组成的索引

**追问：索引的缺点？**
- 占用存储空间
- 降低写操作性能（INSERT/UPDATE/DELETE需要维护索引）
- 过多索引会优化器选择困难

### Q2: 什么是事务？事务的ACID特性？⭐⭐

**简答：**
> 事务是一组操作，要么全部成功，要么全部失败。ACID：原子性、一致性、隔离性、持久性。

**详细回答：**

| 特性 | 英文 | 含义 | 实现方式 |
|------|------|------|----------|
| 原子性 | Atomicity | 事务是不可分割的工作单位 | undo log |
| 一致性 | Consistency | 事务前后数据完整性不变 | 其他三个特性保证 |
| 隔离性 | Isolation | 并发事务互不干扰 | 锁 + MVCC |
| 持久性 | Durability | 事务提交后永久生效 | redo log |

**面试口诀：**
> "原一隔持"（原子性、一致性、隔离性、持久性）

---

### Q3: MySQL的隔离级别？⭐⭐

**简答：**
> 读未提交 → 读已提交 → 可重复读（MySQL默认） → 串行化

**详细回答：**

| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 说明 |
|----------|------|------------|------|------|
| 读未提交 | ✅ | ✅ | ✅ | 可以读到未提交的数据 |
| 读已提交 | ❌ | ✅ | ✅ | 只能读到已提交的数据 |
| 可重复读 | ❌ | ❌ | ✅ | 同一事务内多次读结果一致 |
| 串行化 | ❌ | ❌ | ❌ | 完全串行执行 |

**脏读、不可重复读、幻读：**
- **脏读**：读到其他事务未提交的数据
- **不可重复读**：同一事务内，两次读同一行数据结果不同（被其他事务修改）
- **幻读**：同一事务内，两次查询结果行数不同（被其他事务插入/删除）

**追问：MySQL如何解决幻读？**
> InnoDB在可重复读级别通过MVCC + Next-Key Lock解决大部分幻读问题。

---

### Q4: 什么是MVCC？⭐⭐⭐

**简答：**
> MVCC（多版本并发控制）通过保存数据的历史版本，实现读写不阻塞，提高并发性能。

**详细回答：**

**实现原理：**
每行数据有两个隐藏字段：
- **trx_id**：最近修改该行的事务ID
- **roll_pointer**：指向undo log中该行的上一个版本

**ReadView（读视图）：**
- **m_ids**：当前活跃（未提交）的事务ID列表
- **min_trx_id**：活跃事务中最小的ID
- **max_trx_id**：下一个要分配的事务ID
- **creator_trx_id**：创建该ReadView的事务ID

**可见性判断：**
1. trx_id < min_trx_id → 可见（事务已提交）
2. trx_id >= max_trx_id → 不可见（事务在ReadView之后开始）
3. min_trx_id <= trx_id < max_trx_id → 看是否在m_ids中

## 二、索引深入

### Q5: 什么是覆盖索引？⭐⭐

**简答：**
> 查询的列都在索引中，不需要回表查询数据行。

**详细回答：**
```sql
-- 假设有联合索引 idx_name_age(name, age)
-- 覆盖索引：查询列都在索引中
SELECT name, age FROM user WHERE name = '张三';
-- 不需要回表，直接从索引中获取数据

-- 非覆盖索引：需要回表
SELECT name, age, email FROM user WHERE name = '张三';
-- 需要先查索引得到主键，再回表查email
```

**追问：什么是回表？**
> 通过二级索引查到主键后，再根据主键去聚簇索引查完整数据的过程。

---

### Q6: 索引失效的场景？⭐⭐

**简答：**
> 函数操作、隐式转换、LIKE左模糊、OR条件、不满足最左前缀。

**详细回答：**

| 场景 | 示例 | 原因 |
|------|------|------|
| 对索引列使用函数 | `WHERE YEAR(create_time) = 2026` | 索引存的是原始值 |
| 隐式类型转换 | `WHERE phone = 13800138000`（phone是varchar） | 类型不匹配 |
| LIKE左模糊 | `WHERE name LIKE '%张'` | 无法利用B+树有序性 |
| OR条件 | `WHERE name = '张' OR age = 18` | 可能导致全表扫描 |
| 不满足最左前缀 | 联合索引(a,b,c)，查询条件只有b和c | 联合索引从左匹配 |
| IS NULL / IS NOT NULL | `WHERE name IS NULL` | 视数据分布而定 |
| != 或 <> | `WHERE status != 1` | 可能导致全表扫描 |

---

### Q7: 什么是最左前缀原则？⭐⭐

**简答：**
> 联合索引(a,b,c)相当于创建了(a)、(a,b)、(a,b,c)三个索引，查询条件必须从最左列开始匹配。

**详细回答：**
```sql
-- 联合索引 idx_abc(a, b, c)

-- ✅ 走索引
WHERE a = 1
WHERE a = 1 AND b = 2
WHERE a = 1 AND b = 2 AND c = 3

-- ✅ 走索引（MySQL优化器会调整顺序）
WHERE b = 2 AND a = 1
WHERE c = 3 AND a = 1 AND b = 2

-- ❌ 不走索引
WHERE b = 2
WHERE c = 3
WHERE b = 2 AND c = 3
```

## 三、SQL高频题

### Q8: GROUP BY和HAVING的区别？⭐

**简答：**
> GROUP BY用于分组，HAVING用于过滤分组后的结果。WHERE在分组前过滤，HAVING在分组后过滤。

**详细回答：**
```sql
-- 统计每个班级的平均分，只显示平均分>80的班级
SELECT class_id, AVG(score) as avg_score
FROM student
GROUP BY class_id
HAVING AVG(score) > 80

-- 执行顺序：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
```

**追问：WHERE和HAVING的区别？**
- WHERE：分组前过滤，不能用聚合函数
- HAVING：分组后过滤，可以用聚合函数

---

### Q9: LEFT JOIN、RIGHT JOIN、INNER JOIN的区别？⭐

**简答：**
> INNER返回两表匹配行，LEFT返回左表全部+右表匹配行，RIGHT返回右表全部+左表匹配行。

**详细回答：**
```sql
-- INNER JOIN：只返回两表都匹配的行
SELECT * FROM A INNER JOIN B ON A.id = B.a_id

-- LEFT JOIN：返回左表所有行，右表没有匹配则为NULL
SELECT * FROM A LEFT JOIN B ON A.id = B.a_id

-- RIGHT JOIN：返回右表所有行，左表没有匹配则为NULL
SELECT * FROM A RIGHT JOIN B ON A.id = B.a_id
```

**面试口诀：**
> "INNER取交集，LEFT保左表，RIGHT保右表"

---

### Q10: SQL查询优化技巧？⭐⭐

**简答：**
> 避免SELECT *、合理使用索引、减少子查询、避免全表扫描。

**详细回答：**

| 技巧 | 示例 | 原因 |
|------|------|------|
| 避免SELECT * | `SELECT id, name FROM user` | 减少数据传输 |
| 使用覆盖索引 | 查询列都在索引中 | 避免回表 |
| 避免子查询 | 用JOIN替代 | 子查询效率低 |
| 使用LIMIT | `LIMIT 100` | 减少返回数据量 |
| 避免OR | 用UNION替代 | OR可能导致索引失效 |
| 合理使用索引 | 分析EXPLAIN结果 | 避免全表扫描 |
| 批量操作 | 批量INSERT | 减少网络往返 |

## 四、Redis基础

### Q11: Redis有哪些数据类型？⭐

**简答：**
> String、List、Hash、Set、Sorted Set（ZSet）

**详细回答：**

| 类型 | 说明 | 典型应用 |
|------|------|----------|
| String | 字符串、数字 | 缓存、计数器、分布式锁 |
| List | 有序列表 | 消息队列、最新消息 |
| Hash | 哈希表 | 用户信息、商品详情 |
| Set | 无序集合 | 标签、共同好友 |
| ZSet | 有序集合 | 排行榜、延迟队列 |

---

### Q12: Redis为什么这么快？⭐⭐

**简答：**
> 内存存储、单线程避免上下文切换、IO多路复用、高效数据结构。

**详细回答：**
1. **内存存储**：数据在内存中，读写速度是磁盘的10万倍
2. **单线程**：避免上下文切换和锁竞争（6.0后IO多线程，命令执行仍单线程）
3. **IO多路复用**：epoll模型，一个线程处理多个连接
4. **高效数据结构**：SDS、ziplist、quicklist等优化结构
