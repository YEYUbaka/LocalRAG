# RAG 技术入门指南

## 什么是 RAG？

RAG（Retrieval-Augmented Generation，检索增强生成）是一种结合了信息检索和文本生成的 AI 技术架构。它由 Facebook AI Research（现 Meta AI）在 2020 年提出。

RAG 的核心思想是：在大语言模型（LLM）生成回答之前，先从外部知识库中检索相关信息，然后将检索到的内容作为上下文提供给 LLM，让 LLM 基于这些信息生成更准确、更有依据的回答。

## RAG 的工作流程

RAG 系统的工作流程分为两个阶段：

### 离线阶段（知识入库）

1. **文档解析**：将各种格式的文档（PDF、Word、Markdown 等）解析为纯文本
2. **文本分块**：将长文本切分为较小的片段（chunks），通常 500-1000 个字符
3. **向量化**：使用 Embedding 模型将文本块转换为向量表示
4. **存储**：将向量存入向量数据库（如 ChromaDB、Milvus、Pinecone）

### 在线阶段（问答检索）

1. **问题向量化**：将用户的问题转换为向量
2. **相似度检索**：在向量数据库中找到与问题最相关的文本片段
3. **Prompt 组装**：将检索到的片段作为上下文，结合用户问题组装 Prompt
4. **LLM 生成**：调用大语言模型生成最终答案

## RAG 的优势

- **减少幻觉**：LLM 基于检索到的真实信息回答，而非仅依赖训练数据
- **知识可更新**：只需更新知识库，无需重新训练模型
- **来源可追溯**：答案可以引用具体的文档来源
- **成本可控**：相比微调大模型，RAG 的实施成本更低

## 常见的 Embedding 模型

| 模型 | 维度 | 特点 |
|------|------|------|
| OpenAI text-embedding-3-small | 1536 | 商用，效果好 |
| BAAI/bge-small-zh-v1.5 | 512 | 中文优秀，可本地运行 |
| sentence-transformers/all-MiniLM-L6-v2 | 384 | 英文为主，轻量 |
| Moka AI/m3e-base | 768 | 中文，开源 |

## 向量数据库对比

- **ChromaDB**：纯 Python，轻量，适合本地开发和小规模应用
- **Milvus**：分布式架构，适合大规模生产环境
- **Pinecone**：全托管云服务，无需运维
- **Weaviate**：支持混合搜索（向量+关键词）

## 最佳实践

1. **分块策略**：chunk_size 建议 500-1000 字符，overlap 50-100 字符
2. **Top-K 选择**：通常取 3-5 个检索结果
3. **Prompt 设计**：明确要求 LLM 基于上下文回答，并标注引用来源
4. **混合检索**：结合向量检索和关键词检索（BM25），提升专有名词的检索效果
