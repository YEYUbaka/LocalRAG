# 简历优化指南

> 适用对象：大学生求职者
> 更新时间：2026-06-17

---

## 一、简历基本结构

### 标准简历模块

```
1. 个人信息（姓名、电话、邮箱、GitHub/博客）
2. 教育背景（学校、专业、GPA/排名）
3. 技能清单（语言、框架、工具）
4. 项目经历（2-3个核心项目）
5. 实习经历（如有）
6. 竞赛/获奖（如有）
7. 其他（论文、开源贡献等）
```

---

## 二、个人信息

### 必填项

| 项目 | 说明 | 示例 |
|------|------|------|
| 姓名 | 真实姓名 | 涂维轩 |
| 电话 | 手机号 | 189-XXXX-0991 |
| 邮箱 | 专业邮箱 | yeyubaka@qq.com |
| 求职意向 | 明确岗位 | 测试开发工程师 |

### 可选项

| 项目 | 说明 | 示例 |
|------|------|------|
| GitHub | 技术作品展示 | github.com/xxx |
| 博客 | 技术文章 | yeyubaka.top |
| 个人网站 | 作品集 | xxx.com |

### 不要写的信息

- ❌ 身份证号（隐私）
- ❌ 家庭住址（不必要）
- ❌ 婚姻状况（不相关）
- ❌ 照片（除非要求）

## 三、教育背景

### 格式

```
武汉工程科技学院 | 人工智能 | 本科 | 2023.09 - 2027.06
- 专业排名前5%
- 主修课程：Python程序设计、数据结构、机器学习、深度学习
```

### 注意事项

- GPA/排名如果好看就写，不好看可以不写
- 主修课程只写与岗位相关的
- 不要写高中信息

## 四、技能清单

### 技能分级

```
熟悉 > 掌握 > 了解

- 熟悉：Python、MySQL、pytest、Postman
- 掌握：FastAPI、React、Git、Linux
- 了解：Docker、Redis、Nginx
```

### 技能分类

```markdown
编程语言：Python、Java、SQL
后端框架：FastAPI、Spring Boot
前端框架：React、Vue
数据库：MySQL、Redis、ChromaDB
测试工具：pytest、Postman、Selenium
开发工具：Git、Docker、Linux、Nginx
AI相关：LangChain、OpenAI API、RAG
```

### 避坑

- ❌ 不要写"精通"（除非你真的是专家）
- ❌ 不要写太基础的技能（如"会用Office"）
- ❌ 不要写与岗位无关的技能
- ✅ 根据JD调整技能顺序，把匹配的放前面

## 五、项目经历

### 项目描述模板

```
项目名称 | 你的角色 | 时间段
技术栈：Python, FastAPI, React, MySQL, ChromaDB

项目描述：一句话说明项目是什么

职责与成果：
- 负责XXX模块，实现了XXX功能
- 使用XXX技术解决了XXX问题
- 项目成果：XXX（量化数据）
```

### 示例

```
智学伴 - AI个性化学习平台 | 后端开发 & 测试 | 2025.09 - 2026.03
技术栈：Python, FastAPI, React, MySQL, ChromaDB, pytest

项目描述：基于RAG技术的AI学习平台，支持教材上传、智能问答、学习计划生成。

职责与成果：
- 搭建pytest测试框架，设计MockProvider解耦外部AI接口，覆盖6个核心Service
- 使用Postman进行接口测试，发现并修复2个鉴权安全漏洞
- 实现SSE流式响应，支持打字机效果的实时AI回答
- 项目获校级计算机设计大赛二等奖
```

## 六、STAR法则写项目

### STAR法则

| 字母 | 含义 | 说明 |
|------|------|------|
| S | Situation | 背景：项目是什么，为什么做 |
| T | Task | 任务：你负责什么 |
| A | Action | 行动：你做了什么，怎么做的 |
| R | Result | 结果：取得了什么成果 |

### 示例对比

**❌ 不好的写法：**
> 负责后端开发，写了接口和测试

**✅ 好的写法（STAR）：**
> 针对AI接口测试的不确定性（S），负责搭建自动化测试框架（T），设计MockProvider类解耦外部依赖，编写6个测试模块覆盖正常/异常/降级三类场景（A），测试覆盖率达到80%，发现2个高危安全漏洞（R）

## 七、量化成果

### 常用量化维度

| 维度 | 示例 |
|------|------|
| 效率提升 | "部署时间从30分钟缩短到5分钟" |
| 质量改善 | "测试覆盖率达到80%" |
| 性能指标 | "响应时间<2秒，并发支持100+" |
| 发现问题 | "发现2个高危安全漏洞" |
| 获奖情况 | "获校级计算机设计大赛二等奖" |

### 没有数据怎么办？

- **估算**：根据实际情况合理估算
- **对比**：和之前的状态对比
- **定性**：用"显著提升"、"大幅改善"等词
- **反馈**：引用导师/同事的评价

## 八、简历格式

### 排版原则

- **一页纸**：应届生简历控制在一页
- **简洁清晰**：不要花哨的设计
- **重点突出**：项目和技能放在显眼位置
- **PDF格式**：避免格式错乱

### 文件命名

```
姓名-岗位-学校.pdf
示例：涂维轩-测试开发工程师-武汉工程科技学院.pdf
```

## 九、投递技巧

### 投递时间

- **最佳时间**：周二到周四，上午9-11点
- **避免时间**：周一（HR最忙）、周五下午（准备下班）

### 投递数量

- **海投期**：每天投递10-20家
- **精投期**：每天3-5家，认真准备

### 跟进策略

- 投递后1周无回复，可主动询问
- 面试后3天无回复，可发感谢信跟进

## 十、避坑指南

### ❌ 常见错误

1. **简历太长**：应届生不要超过1页
2. **技能堆砌**：列出20+技能，显得不专业
3. **项目流水账**：只写做了什么，不写成果
4. **格式混乱**：字体不统一、间距不一致
5. **错别字**：显得不认真

### ✅ 正确做法

1. **精简内容**：只保留与岗位相关的
2. **突出重点**：技能5-8个，项目2-3个
3. **量化成果**：用数据说话
4. **统一格式**：使用模板，保持一致
5. **多次检查**：让同学帮忙review
