## 一、大模型基础

### Q1: 什么是大语言模型（LLM）？⭐

**简答：**
> 大语言模型是基于Transformer架构、在海量文本上训练的深度学习模型，能理解和生成自然语言。

**详细回答：**
- **架构**：基于Transformer的Decoder部分
- **训练**：预训练（无监督）+ 微调（有监督）
- **能力**：文本生成、问答、翻译、代码生成等
- **代表**：GPT系列、Claude系列、Qwen、DeepSeek、GLM

**追问：什么是Transformer？**
> Transformer是2017年Google提出的架构，核心是自注意力机制（Self-Attention），能并行处理序列数据，解决了RNN的长距离依赖问题。

---

### Q2: 什么是Prompt Engineering？⭐⭐

**简答：**
> Prompt Engineering是设计和优化提示词，引导大模型输出期望结果的技术。

**详细回答：**

**常用技巧：**
1. **明确指令**：告诉模型具体要做什么
2. **角色设定**：让模型扮演特定角色
3. **少样本学习（Few-shot）**：给几个示例
4. **思维链（CoT）**：让模型展示推理过程
5. **输出格式约束**：指定JSON、Markdown等格式

**示例：**
```
# 不好的Prompt
帮我写个邮件

# 好的Prompt
你是一个专业的商务邮件撰写者。请帮我写一封邮件，主题是：向客户道歉因为发货延迟。
要求：
1. 语气诚恳、专业
2. 包含延迟原因说明
3. 提供补偿方案
4. 字数200字以内
```

### Q3: 什么是RAG？⭐⭐

**简答：**
> RAG（检索增强生成）是将检索到的外部知识注入大模型，解决模型知识过时和幻觉问题。

**详细回答：**

**RAG工作流程：**
```
用户问题 → 向量检索 → 获取相关文档片段 → 拼接Prompt → LLM生成回答
```

**核心组件：**
1. **文档加载**：解析PDF、Word、网页等
2. **文本分块**：将文档切分成小段
3. **向量化**：用Embedding模型将文本转为向量
4. **向量存储**：存入向量数据库（如ChromaDB、Milvus）
5. **检索**：根据问题检索相关片段
6. **生成**：将检索结果和问题一起发给LLM

**RAG的优势：**
- 知识可更新：只需更新文档库
- 减少幻觉：基于真实文档回答
- 可追溯：可以给出引用来源
- 成本低：不需要微调模型

---

### Q4: 什么是向量数据库？⭐⭐

**简答：**
> 向量数据库专门存储和检索向量数据，通过余弦相似度等算法找到最相似的向量。

**详细回答：**

**常见向量数据库：**
- ChromaDB（轻量，适合原型）
- Milvus（分布式，生产级）
- Pinecone（云服务）
- FAISS（Facebook开源，纯库）

**相似度算法：**
- 余弦相似度：衡量向量方向的相似性
- 欧氏距离：衡量向量空间中的距离
- 内积：考虑向量方向和大小

## 二、Agent开发

### Q5: 什么是AI Agent？⭐⭐

**简答：**
> AI Agent是能够自主感知环境、做出决策、执行行动的智能体，通常基于LLM作为"大脑"。

**详细回答：**

**Agent核心组件：**
1. **LLM（大脑）**：理解和推理
2. **工具（手脚）**：搜索、计算、API调用等
3. **记忆（经验）**：短期记忆（对话历史）和长期记忆（知识库）
4. **规划（策略）**：任务分解和执行计划

**常见Agent架构：**
- **ReAct**：Reasoning + Acting，思考→行动→观察循环
- **Plan-and-Execute**：先规划再执行
- **Reflexion**：自我反思和改进

---

### Q6: 什么是ReAct模式？⭐⭐⭐

**简答：**
> ReAct是"思考-行动-观察"循环，Agent先推理要做什么，再执行动作，最后观察结果。

**详细回答：**

```
Thought: 我需要查找今天的天气
Action: search("今天北京天气")
Observation: 今天北京晴，最高温度28度
Thought: 我已经获取到天气信息，可以回答用户了
Action: respond("今天北京天气晴朗，最高温度28度。")
```

**ReAct的优势：**
- 可解释：可以看到推理过程
- 灵活：根据观察动态调整策略
- 可纠错：发现错误可以重新推理

### Q7: Agent的工具调用机制？⭐⭐⭐

**简答：**
> Agent通过Function Calling机制调用工具，LLM决定调用哪个工具、传什么参数，执行后将结果返回给LLM。

**详细回答：**

**工具注册：**
```python
tools = [
    {
        "name": "search",
        "description": "搜索互联网信息",
        "parameters": {
            "query": {"type": "string", "description": "搜索关键词"}
        }
    },
    {
        "name": "calculate",
        "description": "数学计算",
        "parameters": {
            "expression": {"type": "string", "description": "数学表达式"}
        }
    }
]
```

**调用流程：**
1. 用户提问 → LLM分析需要什么工具
2. LLM输出工具调用指令（JSON格式）
3. 系统执行工具，获取结果
4. 将结果返回给LLM
5. LLM综合结果生成最终回答

### Q8: 如何处理Agent的死循环问题？⭐⭐⭐

**简答：**
> 设置最大循环次数、响应去重、超时机制、降级策略。

**详细回答：**

**1. 最大循环次数**
```python
max_iterations = 10
for i in range(max_iterations):
    # Agent循环
    if should_stop:
        break
```

**2. 响应去重**
```python
from difflib import SequenceMatcher

def is_duplicate(new_response, history, threshold=0.8):
    for old_response in history:
        similarity = SequenceMatcher(None, new_response, old_response).ratio()
        if similarity > threshold:
            return True
    return False
```

**3. 超时机制**
```python
import signal

def timeout_handler(signum, frame):
    raise TimeoutError("Agent执行超时")

signal.signal(signal.SIGALRM, timeout_handler)
signal.alarm(30)  # 30秒超时
```

**4. 降级策略**
- 搜索失败 → 使用缓存结果
- 工具调用超时 → 跳过该工具
- 多次失败 → 返回默认回答

## 三、Prompt工程进阶

### Q9: 什么是思维链（Chain of Thought）？⭐⭐

**简答：**
> 思维链是让模型展示推理过程的提示技巧，通过"让我们一步步思考"引导模型分步推理。

**详细回答：**
```
# 普通提示
Q: 一个商店有23个苹果，卖掉了一些后剩下8个，卖掉了多少个？
A: 15个

# 思维链提示
Q: 一个商店有23个苹果，卖掉了一些后剩下8个，卖掉了多少个？
A: 让我们一步步思考：
1. 商店最初有23个苹果
2. 卖掉一些后剩下8个
3. 卖掉的数量 = 最初数量 - 剩余数量
4. 卖掉的数量 = 23 - 8 = 15
所以卖掉了15个苹果。
```

**思维链的优势：**
- 提高复杂推理的准确率
- 让模型输出更可解释
- 方便调试和改进

### Q10: 什么是Few-shot Learning？⭐⭐

**简答：**
> Few-shot Learning是在Prompt中给模型几个示例，让模型学习任务模式。

**详细回答：**
```
# Zero-shot（无示例）
将以下句子分类为正面或负面："这个产品很好用"

# Few-shot（有示例）
将以下句子分类为正面或负面：

句子："服务态度很差" → 负面
句子："物超所值" → 正面
句子："包装破损" → 负面

句子："这个产品很好用" →
```

## 四、向量与Embedding

### Q11: 什么是Embedding？⭐⭐

**简答：**
> Embedding是将文本、图片等转换为固定长度的向量表示，向量之间的距离表示语义相似度。

**详细回答：**

**Embedding的特点：**
- 语义相近的文本，向量距离近
- 语义不同的文本，向量距离远
- 支持向量运算（如：国王 - 男人 + 女人 ≈ 女王）

**常见Embedding模型：**
- OpenAI text-embedding-ada-002
- BGE系列（BAAI）
- M3E（中文）
- Sentence-Transformers

**应用场景：**
- 语义搜索
- 文档聚类
- 推荐系统
- RAG检索

---

### Q12: 如何优化RAG检索效果？⭐⭐⭐

**简答：**
> 优化分块策略、使用混合检索、Rerank重排序、查询改写。

**详细回答：**

**1. 分块策略优化**
- 合适的chunk_size（500-1000字符）
- 适当的overlap（50-100字符）
- 按语义分块而非固定长度

**2. 混合检索**
```
向量检索（语义相似） + BM25检索（关键词匹配） → RRF融合
```

**3. Rerank重排序**
- 用交叉编码器对检索结果重新排序
- 过滤低质量结果（设置阈值）

**4. 查询改写**
- LLM将用户问题改写成多个变体
- 每个变体分别检索，合并结果

## 五、模型部署与优化

### Q13: 什么是模型量化？⭐⭐

**简答：**
> 模型量化是将模型参数从高精度（FP32）转为低精度（INT8/INT4），减少内存和计算开销。

**详细回答：**

| 精度 | 大小（7B模型） | 速度 | 效果 |
|------|----------------|------|------|
| FP32 | 28GB | 慢 | 最好 |
| FP16 | 14GB | 中 | 好 |
| INT8 | 7GB | 较快 | 略降 |
| INT4 | 3.5GB | 快 | 有损 |

**量化方法：**
- GPTQ：训练后量化
- AWQ：激活感知量化
- GGUF：llama.cpp格式

---

### Q14: 什么是模型微调（Fine-tuning）？⭐⭐

**简答：**
> 微调是在预训练模型基础上，用特定领域数据继续训练，让模型适应特定任务。

**详细回答：**

**微调方法：**
1. **全参数微调**：更新所有参数，效果好但成本高
2. **LoRA**：只训练低秩适配器，成本低效果好
3. **QLoRA**：量化 + LoRA，进一步降低成本

**微调 vs RAG：**

| 维度 | 微调 | RAG |
|------|------|-----|
| 知识更新 | 需要重新训练 | 更新文档即可 |
| 成本 | 高（需要GPU） | 低 |
| 效果 | 特定任务更好 | 通用性更好 |
| 幻觉 | 仍有 | 基于文档，较少 |
