LocalRAG · 前端改版方案

三个设计方向，同一份真实语料

三份稿子回答的是同一个问题：一个本地 RAG 知识库，界面该长什么样才不像默认模板。 它们都用你 test_docs/ 里的真实文档和真实检索参数， 都能点、能输入。差别在结构赌注，不在配色深浅。

三个方向都做了

浅色底、脱离 antd 默认蓝、去掉 style={{}} 内联样式、建立 token 变量、字号阶梯、键盘焦点可见、尊重 prefers-reduced-motion。

共同的核心主张

引用不再是被丢在气泡底部的灰标签。三份稿子都把出处、排序和召回来源当作一等公民 —— 这才是 RAG 界面区别于普通聊天框的地方。

都用真实数据

语料取自 interview-ai-engineer.md、RAG技术入门.md、interview-project-star.md；参数取自你的 top_k=5、retrieval_top_k=20、rerank_threshold=1.0。

风险 最大的赌注 —— 老用户可能觉得「对话感」消失了。多轮追问的呈现方式需要再设计（稿子里先用了引文块）。

怎么选

  1. 想要最稳的一步到位：选 A。三栏结构和你现在的布局最接近，改动风险最低，但视觉语言完全换掉了。衬线正文是这个方案里唯一需要你点头的赌注。
  2. 想强调「这是个技术工具」：选 B。信息密度最高，检索流水线直接变成卖点。适合你自己天天用，也适合放进面试作品集讲。
  3. 想做得最不一样：选 C。把问答当读文献，气质最独特。代价是交互习惯改动最大。
  4. 也可以取交集。比如：A 的三栏 + B 的流水线状态条 + C 的段落批注联动。三个签名并不互斥，我可以在落地时合成一版。

选定后我会把它落成真实代码：在 ConfigProvider 建一套 theme.token， 用 theme.useToken() 替换掉那 108 处内联样式，顺手修掉 DocumentList.tsx:438 的 #1890ff 残留和浅色界面里嵌 oneDark 代码块的问题。

三份稿子都是单文件静态 HTML，无外部依赖、无网络请求，直接双击即可打开。 稿子里的交互（点引用、点阶段、滚动跟随、输入回车）都是可用的，方便你判断手感而不只是看外观。
